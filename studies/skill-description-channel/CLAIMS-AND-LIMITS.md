# Claims and limits

| Supported by the released study | Not established |
| --- | --- |
| One opaque imperative caused frequent, badly calibrated natural routing on one frozen Codex stack. | That the model understood ZANQURIL or that invented words reliably improve routing. |
| No Codex or Claude online cell made a qualifying ZANQURIL web search. | That agents never retrieve unfamiliar skill concepts online under harder tasks. |
| Visible facts, some encoded carriers, and confusables changed answers. | Arbitrary instruction execution, persistence, credential access, mutation, or exfiltration. |
| Plain factual content entered work products without body loads, and one fact effect survived a forced full body. | That every description payload survives every body, task, runtime, or model. |
| Sonnet provider refusals varied by carrier and within one control arm; Haiku had none. | A dependable provider-guardrail policy or a causal explanation for the model difference. |
| Current public SkillSieve code and our linter missed all five Codex-responsive description arms. | That every public scanner fails or that either tool is generally ineffective. |
| AI reliance is increasing and generated political messages can persuade in controlled studies. | A real description-borne influence campaign or any demonstrated political outcome from these tests. |

## Measurement boundaries

- Description exposure, selection or declination, body delivery, retrieval,
  run completion, and enacted behavior are distinct events.
- Task-labelled routing suites provide TP/TN/FP/FN denominators, but the tested
  runtimes did not expose whether a particular catalog entry was considered and
  declined or why.
- Forcing a full body can test whether an observed effect survives delivery. It
  cannot test a description's suppressive non-load branch because it removes
  that branch by construction.
- A valid provider cell is not the same thing as an oracle pass, a canary-bearing
  answer, or mechanically enacted behavior.
- Claude model, runtime, and replacement policy are confounded with the Codex
  comparison and are not pooled.
- The initial release includes aggregate results and reports, not every native
  provider trace. Report-level results remain labelled as such.
